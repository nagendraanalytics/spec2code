This report scans non-deleted subject records within each protocol and independently flags any subjects sharing an identical Screening Number or an identical Randomization Number (via the Subject Assignment form). Each qualifying subject is output with Country, Site, Subject Number, Screening Number, and Randomization Number, plus a derived 'Duplicates' label identifying which type of match caused inclusion. Output is organized as two separate sorted groups -- one for Randomization Number duplicates sorted by Duplicates/Randomization Number/Subject Number, and one for Screening Number duplicates sorted by Duplicates/Screening Number/Subject Number.

1. Establish the population: gather all non-deleted subject records (from Subjects and Subject Assignment forms) within a given protocol, since the spec explicitly states 'Report should not display deleted records.'
2. Check 1 -- Randomization Number duplicates: compare the 'Treatment Randomization Number' value (from Subject Assignment form) across all subjects within the same protocol; if two or more subjects share an identical Randomization Number, those subjects' records qualify for output.
3. Check 2 -- Screening Number duplicates: independently compare the 'Screening Number' value (from Subject Assignment form) across all subjects within the same protocol; if two or more subjects share an identical Screening Number, those subjects' records also qualify for output.
4. The spec says the report displays output 'if subjects have identical Randomization Numbers' OR 'if subjects have identical Screening Numbers' -- these are two separate, independent triggers, meaning a subject could appear in the output for either or both reasons.
5. For each qualifying row, derive the 'Duplicates' column: label it 'Randomization Number Duplicate' when the row was flagged due to a matching Randomization Number, or 'Screening Number Duplicate' when flagged due to a matching Screening Number.
6. Populate the remaining output columns for each qualifying subject: Country and Site from Subject Assignment form (Site Country, Site Mnemonic), Subject Number from Subjects form, Screening Number and Randomization Number from Subject Assignment form.
7. Apply sorting: for rows flagged as Randomization Number duplicates, sort by Duplicates, then Randomization Number, then Subject Number; for rows flagged as Screening Number duplicates, sort by Duplicates, then Screening Number, then Subject Number -- implying the two duplicate types are grouped/sorted as separate blocks in the final output.
8. SELECT
  d.SiteCountry AS `Country`,
  d.SiteNumber AS `Site`,
  d.SubjName AS `Subject Number`,
  d.ScreeningNumber AS `Screening Number`,
  d.RandomizationNumber AS `Randomization Number`,
  d.DupFlag AS `Duplicates`
FROM
  (
    SELECT
      `@HDR`.`Site`.`Country` AS SiteCountry,
      `@HDR`.`Site`.`Number` AS SiteNumber,
      `@HDR`.`Subject`.`Name` AS SubjName,
      SASCORRESSNUMIT AS ScreeningNumber,
      ENRMSUBJNUMIT AS RandomizationNumber,
      'Randomization Number Duplicate' AS DupFlag
    FROM `EDC`.`SAFM`
    WHERE `@Form`.`Status` = 'submitted__v'
      AND ENRMSUBJNUMIT IS NOT NULL
      AND ENRMSUBJNUMIT IN (
        SELECT s2.ENRMSUBJNUMIT
        FROM `EDC`.`SAFM` s2
        WHERE s2.`@Form`.`Status` = 'submitted__v'
          AND s2.ENRMSUBJNUMIT = ENRMSUBJNUMIT
        GROUP BY s2.ENRMSUBJNUMIT
        HAVING COUNT(DISTINCT s2.`@HDR`.`Subject`.`ID`) > 1
      )
    UNION ALL
    SELECT
      `@HDR`.`Site`.`Country` AS SiteCountry,
      `@HDR`.`Site`.`Number` AS SiteNumber,
      `@HDR`.`Subject`.`Name` AS SubjName,
      SASCORRESSNUMIT AS ScreeningNumber,
      ENRMSUBJNUMIT AS RandomizationNumber,
      'Screening Number Duplicate' AS DupFlag
    FROM `EDC`.`SAFM`
    WHERE `@Form`.`Status` = 'submitted__v'
      AND SASCORRESSNUMIT IS NOT NULL
      AND SASCORRESSNUMIT IN (
        SELECT s3.SASCORRESSNUMIT
        FROM `EDC`.`SAFM` s3
        WHERE s3.`@Form`.`Status` = 'submitted__v'
          AND s3.SASCORRESSNUMIT = SASCORRESSNUMIT
        GROUP BY s3.SASCORRESSNUMIT
        HAVING COUNT(DISTINCT s3.`@HDR`.`Subject`.`ID`) > 1
      )
  ) d
ORDER BY
  d.DupFlag,
  (CASE WHEN d.DupFlag = 'Randomization Number Duplicate' THEN d.RandomizationNumber ELSE d.ScreeningNumber END),
  d.SubjName

The spec's "Subject Assignment form" and "Subjects" map most closely to the SAFM Form in the provided study metadata, which contains ENRMSUBJNUMIT (treated as the Randomization Number equivalent), SASCORRESSNUMIT (Screening Number), and SADMSUBJIDIT; I used ENRMSUBJNUMIT/SASCORRESSNUMIT as best-fit matches since no explicit "Randomization Number"/"Screening Number"-named items exist in SAFM -- this should be confirmed via DESCRIBE FORM against the study's actual Subject Assignment form mapping. Two UNION ALL branches independently find subjects sharing an identical Randomization Number or Screening Number (using a self-correlated subquery with GROUP BY/HAVING COUNT(DISTINCT Subject) > 1) and tag each row with the appropriate Duplicates label, then the outer query aliases/sorts per the spec (Duplicates, then the matching number field, then Subject Number). SAFM has no DELETEDFM item in the provided metadata, so no deleted-record filter was applied to this Form -- flagging this as a gap since the spec explicitly requires excluding deleted records; if Subject Assignment data actually lives in a different Form with a delete flag, that filter should be added once confirmed.
