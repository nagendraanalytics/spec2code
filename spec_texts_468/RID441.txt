Report ID: RID441

Report Title:
Missing SSC

Description:
This report will list subjects who are missing a Specimen Sample Collection Invoice for specified Sample Description every specific interval of time following Date of Randomization.

Column Heading:
1. Country

2. Site

3. Subject Number

4.Starting Form

5. Starting point

6. Sponsor ID

7. Sample Description

8. Expected Sample Description Date Range

Logic:
Logic 1: Starting Form. Starting point (From supporting document) is <> than NULL

AND

Logic 2: There’s no SSC Sample Description on supporting document Completed within each expect timeframe

AND

Logic 3:  upper limit expect timeframe < System date

AND

Logic 4: OEDRA/PMS1A = NULL

AND

(Logic 5.1 There is not at least one record on the 'Oncologic Treatment' form with ODBX.Date <> NULL

OR 'Expected Timepoint' is before the minimum ODBX.Date entered across all records present in the form

AND

Logic 5.2 There is not at least one record on the 'Oncologic Radiation' form with ORAD2.Start Date <> NULL AND ORAD2.Reason <> Palliative

OR 'Expected Timepoint' is before the minimum ORAD2.Start Date entered across all records present in the form)

AND

Logic 5.3 There is not at least one record on the 'Oncologic Surgery' form with OSOFX.Date <> NULL

OR 'Expected Timepoint' is before the minimum OSOFX.Date entered across all records present in the form)

Requires supporting document to be named ONC_SSC_002_supp_<xxxxxxx>.csv and will contain the following columns and associated content:

1.	Criteria_Form - Unique value in each group, specified as 'NA' if it is checked for all subjects

2.	Criteria_Itemquestion - Unique value in each group, specified as 'NA' if it is checked for all subjects

3.	Criteria_Value - Unique value in each group, specified as 'NA' if it is checked for all subjects

4.	Phase Order – Enter value matching the corresponding treatment phase defined per study_phase_supp_doc.csv

5.	Starting Point – Enter SR/DOV, if “SR” is selected, the report will count since the date of assessment from SR eCRF and if “DOV” is selected, the report will count since the date of visit from the first visit of each treatment phase as provided in the study phase supporting document

6.	Sample Description – Enter the corresponding Sample Description that the report should output

7.	Frequency – Value should be provided in WEEKS: Enter the number of weeks that the report should use based on the Phase Order and Starting Point to output the missing Sample Description for the different timepoints. For example: ‘Blood for PSA needs to be collected every 6 weeks following the date of randomization (± 7 days) until week 30', then enter 6. If the frequency changes during the same treatment phase for the same Sample Description, then a new row is expected with a new Frequency. For example: 'Subsequent sample collection should be performed every 12 weeks (±7 days)' then enter 12 as the new Frequency.

8.	Start Week: Value should be provided in WEEKS: Enter the number of weeks equivalent to the first timepoint when the report should output the missing Sample Description. For example: ‘Blood for PSA needs to be collected every 6 weeks following the date of randomization (± 7 days) until week 30', then enter 6. If the frequency changes during the same treatment phase for the same Sample Description, then a new row is expected with a new start week for example: 'Subsequent sample collection should be performed every 12 weeks (±7 days)' then enter 42 (last stop week + new frequency: 30+12 = 42) as the new start week.

9.	Stop Week: Value should be provided in WEEKS: Enter the number of weeks equivalent to the last timepoint when the report should output the missing Sample Description. For example: ‘Blood for PSA needs to be collected every 6 weeks following the date of randomization (± 7 days) until week 30', then enter 30. This value can be entered as ‘NA’ if per protocol the report should keep outputting missing Sample Description until the subject completes PMS1A/OEDRA (end of efficacy assessments) or completes ODBF/ORAD2/OSOF (initiates a new anti-cancer therapy)

10.	Lower Window of Days - Value should be provided in DAYS: Enter the number of days for the lower window equivalent to each frequency. For example: ‘Blood for PSA needs to be collected every 6 weeks following the date of randomization (± 7 days) until week 30' then enter 7

11.	Upper Window of Days – Value should be provided in DAYS: Enter the number of days for the upper window equivalent to each frequency. For example: ‘Blood for PSA needs to be collected every 6 weeks following the date of randomization (± 12 days) until week 30' then enter 12

The number of rows in the supporting document will be represented in the Report Header as "# of rows for customization".

The actual information provided by the supporting doc can be outputted by selecting Y in the parameter "Supporting doc Page".

The supporting document is required for all trials if treatment phase is applied to logic, even if only one treatment phase is present.

This supporting document is only required to be created once per trial. If it was already created and uploaded, there is no need to duplicate it.

The supporting document should be named as study_phase_supp_<xxxxxxx>.csv and will contain the following columns and associated content:

One row for each Treatment Phase

1. Phase Order: required,the order on which phases will appear on protocol

2. Treatment Phase: name of each study phase (Intial Treatment Phase, Neodjuvant Phase, Secon Course Phase)

3. First Visitmnemonic of Treatment Phase: required,the first visit on which treatment is expected to be administered on each phase.

e.g.

Phase Order, Treatment phase, First Visitmnemonic of Treatment Phase

1,Initial Treatment Phase,Cycle 1

2,Second Course Phase,Second Course Cycle 1

The treatment phase will be identified as following:

Initial Treatment Phase: Cycle 1 <= Form.Date < Second Course Cycle 1

Second Course Phase: Second Course Cycle 1 <= Form.Date

Form.Date include: SSC.Date/Time Specimen Obtained, PMS1A.Date of Assessment

Notes:

Note 1: Please exclude deleted record.

Note 2.

Steps to calculate the ‘Timepoint’ and the 'Expected Timeframe':

A.      Calculate different timepoints by doing the following mathematical operation:

Timepoint 1: ‘Start Item Date’ + Start week

Timepoint 2: ‘Start Item Date’ + Start week + 1*Frequency

Timepoint 3: ‘Start Item Date’ + Start week + 2*Frequency

Timepoint N: ‘Start Item Date’ + Start week + (N-1)*Frequency

B.      Timepoints calculated on step A should be: ‘Start Item Date’ + Start week <= Timepoint N <= ‘Start Item Date’ + ‘Stop week’

C.      Expected Timeframe is From Timepoint N - 'Lower window of days' to Timepoint N + 'Upper window of days'

Example:

A.      Start Date Item = 01-Jan-2020

B.      Start week = 12

C.      Stop week = 108

D.      Frequency = 12

E.      Lower window of days = 14

F.      Upper window of days = 14

Timepoint 1 = 01-Jan-2020 + 12 weeks = 25-Mar-2020

Expected Timeframe 1 = From 11-Mar-2020 to 08-Apr-2020

Timepoint 2 = 01-Jan-2020 + 12 weeks + 12 weeks = 17-Jun-2020

Expected Timeframe 2 = From 3-Jun-2020 to 1-Jul-2020

Timepoint 3 = 01-Jan-2020 + 12 weeks + 12 weeks + 12weeks = 09-Sep- 2020

Expected Timeframe 3 = From 26-Aug-2020 to 23-Sep-2020

Note 3  . The report logic should be checked within the same treatment phase defined in the supporting document

Note 4: No Output is expected, if the Starting point (From supporting document) + upper limit form the Window of weeks and days (From supporting document) > System date.

For example if:

Starting Form(From supporting document)= SR

Starting point (From supporting document)=01/Jan/2021

Window of weeks and days (From supporting document)= 9 weeks +/- 3

No Output is required until 26/March/2021=01/Jan/2021+ 12 Weeks=01/Jan/2021+84 days

Note 5:     ODBX.Date = Imputed Start Date of Regimen/Imputed Start Date of Medication. Use by default 'Imputed Start Date of Regimen'. For newer trials where 'Imputed Start Date of Regimen' is not available use 'Imputed Start Date of Medication'. ODBX forms are included in global supporting document ODBF_supp_doc.

ORAD2.Reason <> Palliative refers to the item 'Reason for Radiation' <> 'Palliative Treatment or Symptom Control' OR 'Palliative Treatment or Symptom Control of Metastatic Disease' for older studies and 'Treatment Category' <> 'Palliative' for newer studies.

OSOFX.Date = Date of Surgery in global supporting document OSOF_supp_doc

Note 6:     When ORAD2.Date or OSOFX.Date are entered as UNK, consider the value as 01 for the day and Jan for the month. Example. UNK/UNK/2020 will be considered as 01/Jan/2020.

Notes for display:

Note 1. For all dates, please display using the format dd/mmm/yyyy

Report Scenarios:
Scenario A, Output = Yes

Subjects who are missing a Specimen Sample Collection Invoice for specified Sample Description (Specify window in supporting document) AND ARM/COHORT/PART (Provided in supporting document) following Date of Randomization/First DOV of treatment phase and PMS1A/OEDRA  is not completed and there’s no new anticancer treatments recorded.

Scenario B, Output = No

Subjects who are missing a Specimen Sample Collection Invoice for specified Sample Description (Specify window in supporting document) AND ARM/COHORT/PART (Provided in supporting document) following Date of Randomization/First DOV of treatment phase and subject has completed PMS1A/OEDRA and there’s no new anticancer treatments recorded.

Scenario C, Output = No

Subjects who are missing a Specimen Sample Collection Invoice for specified Sample Description (Specify window in supporting document) AND ARM/COHORT/PART (Provided in supporting document) following Date of Randomization/First DOV of treatment phase and PMS1A/OEDRA is not completed and there’s at least one new anticancer treatment recorded.

Scenario D, output= No

Subjects who are missing a Specimen Sample Collection Invoice for specified Sample Description (Specify window in supporting document) AND ARM/COHORT/PART (Provided in supporting document) following Date of Randomization/First DOV of treatment phase and subject has completed PMS1A/OEDRA and there’s at least one new anticancer treatment recorded.

Scenario E, output= No

Exclude deleted records

Scenario F= No

Exclude Screen Failure
