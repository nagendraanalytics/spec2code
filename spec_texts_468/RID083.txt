Report ID: RID083

Report Title:
GEF Records with Missing Values

Description:
This report displays all GEF records with null values in required fields. Required fields may vary depending on the type of external data collected. Fields to be checked for missing values are provided per study according to the PSA.

Column Heading:
1. Country

2. Site

3. Screening Number

4. Subject Number

5. Vendor

6. Cohort

7. Visit ID or Number

8. Blinding Flag

9. Collection Date/Time

10. REFID

11. KITID

12. Test

13. Completion status

14. Result or Findings in Original Units

15. Missing Required Field

Logic:
Logic 1.1: GEFCF."ITEMQUESTION" per supporting document is NULL when GEFCF.Test Short Name = "TEST SHORT NAME" per supporting document

AND

Logic 1.2: Conditions per supporting document are met

Notes:

This report checks the following required fields from the GEF form for missing values, for records other than FBR.

GEFCF test short name should not be 'FBR'.

The user will provide the required fields from GEF per PSA and the required tests per the specified Cohort in SR(If applicable) .

Optional field:

1. Report will desplay all GEF records if no required tests per the specified Cohort provided;

2.Cohort may be null if not available in the study.

1. For Blinding Flag <> 'B',

Display as missing if following field is null:

[Test, Result or Finding in Original Units, Original Units, Normal Range Lower Limit Original Units, Normal Range Upper Limit Original Units]

2. For Blinding Flag = 'B',

Note:If Blinded Flag is set on a record, the fields 'Result or Finding in Original Units' with blinded data will display 'xxxx'

Display as missing if following field is null:

[Test, Original Units, Normal Range Lower Limit Original Units, Normal Range Upper Limit Original Units]

Report should not display deleted records. If "Randomized only" parameter selection checkbox  is checked, the report should only output subjects with Randomization number that is not null.

Collection Date and Time field is formatted according to the ISO standard. An example for 12-Jul-2007 at noon is: 2007-07-12T12:00:00 (yyyy-mm-ddThh:mm:ss). However, not all time parts are always present.

The report will display a message if the values mentioned in the supporting document columns "ITEMQUESTION" and/or "CONDITEMQUESTION 1,2,3..N" are not available in the GEFCF form: "The following "itemquestions" are not available in the GEFCF form: ITEMQUESTION 1, ITEMQUESTION 2, ITEMQUESTION N, please check the supporting document"

Requires supporting document to be named EVD002_supp_</Vxxxxxxx>.csv and will contain the following columns and associated content:

If supporting doc is not provided, display the message as "EVD002_JR_STD Supporting Document Not Present for This Trial".

If any field is optional per PSA and does NOT depend on a defined condition, then do NOT list such field in the supporting document

1.	CRITERIA_FORM: SR/TRIGA if the required tests may vary according to the defined Cohort/Arm/Stratification. "NA" if the check is done globally

2.	CRITERIA_ITEMQUESTION: Item within 'CRITERIA_FORM' that allow to distinguish different groups of subjects with the defined Cohort/Arm/Stratification (eg. Cohort on SR eCRF). "NA" if the check is done globally

3.	CRITERIA_VALUE: Option defined in the 'CRITERIA_ITEMQUESTION' that refers to the defined Cohort/Arm/Stratification (eg. cohort A in item 'Cohort' on SR eCRF). "NA" if the check is done globally

4.	VENDOR: Type in the vendor name as transferred by the vendor

5.	ITEMQUESTION: Provide the field that is required for each test (e.g. Result or Finding in Original Units, Category, Completion Status, etc.)

6.	TEST SHORT NAME: Provide the test short name of each test as transferred by the vendor (Multiple “Test Short Name” can be included with comma as a separator in between if having same CRITERIA_FORM,CRITERIA_ITEMQUESTION,CRITERIA_VALUE,VENDOR,ITEMQUESTION,GROUP1,CONDITEMQUESTION1,CONDSYMBOL1,CONDRESULT,GROUPN,CONDITEMQUESTIONN,CONDSYMBOLN,CONDRESULT )

7.	GROUP1: Define a numeric value that will be used to connect the different conditions, if the same group is used across different conditions the connector will be OR, if different groups are used across different conditions the connector will be AND (see examples below for further guidance). Type in "NA" if there is no condition

8.	CONDITEMQUESTION1: Type in the ITEMQUESTION of the first condition (see examples below). Type in "NA" if there is no condition

9.	CONDSYMBOL1: EQUAL/DIFFERENT/LESS/GREATER (see examples below). Type in "NA" if there is no condition

10.	CONDRESULT1: Provide the actual result needed based on the condition, if the condition is to be “EQUAL to NULL” or “DIFFERENT than NULL”, type in the word “NULL” in this column (see examples below). Type in "NA" if there is no condition

11.	GROUPN: If more than (1) condition is needed, create additional columns and continue the numbering (GROUP2, GROUP3, GROUP4..GROUPN). Type in "NA" if there is no condition

12.	CONDITEMQUESTIONN: If more than (1) condition is needed, create additional columns and continue the numbering (CONDITEMQUESTION2, CONDITEMQUESTION3, CONDITEMQUESTION4.. CONDITEMQUESTIONN). Type in "NA" if there is no condition

13.	CONDSYMBOLN: If more than (1) condition is needed, create additional columns and continue the numbering (CONDSYMBOL2, CONDSYMBOL3, CONDSYMBOL4.. CONDSYMBOLN). Type in "NA" if there is no condition

14.	CONDRESULTN: If more than (1) condition is needed, create additional columns and continue the numbering (CONDRESULT2, CONDRESULT3, CONDRESULT4.. CONDRESULTN). Type in "NA" if there is no condition

Example 1: When CRITERIA_FORM, CRITERIA_ITEMQUESTION and CRITERIA_VALUE are needed and there is no need to define a condition

The report will output when Category is null for test TUMSTATE only for subjects enrolled in the Arm 3475 + Capecitabine as defined in the TRIGA eCRF and the same field does NOT depend on any condition

CRITERIA_FORM,CRITERIA_ITEMQUESTION,CRITERIA_VALUE,VENDOR,ITEMQUESTION,TEST SHORT NAME,GROUP1,CONDITEMQUESTION1,CONDSYMBOL1,CONDRESULT1

TRIGA,Arm,3475 and Capecitabine,ICON,Category,TUMSTATE,NA,NA,NA,NA

Example 2: When CRITERIA_FORM, CRITERIA_ITEMQUESTION and CRITERIA_VALUE are not needed and there is no need to define a condition

The report will output when Category is null for test TUMSTATE regardless of the Arm/Cohort/Stratification and the same field does NOT depend on any condition

CRITERIA_FORM,CRITERIA_ITEMQUESTION,CRITERIA_VALUE,VENDOR,ITEMQUESTION,TEST SHORT NAME,GROUP1,CONDITEMQUESTION1,CONDSYMBOL1,CONDRESULT1

NA,NA,NA,ICON,Category,TUMSTATE,NA,NA,NA,NA

Example 3: Define a simple condition in the supporting document

The report will output when Category is null for test TUMSTATE when Completion Status is different than not done

CRITERIA_FORM,CRITERIA_ITEMQUESTION,CRITERIA_VALUE,VENDOR,ITEMQUESTION,TEST SHORT NAME,GROUP1,CONDITEMQUESTION1,CONDSYMBOL1,CONDRESULT1

NA,NA,NA,ICON,Category,TUMSTATE,1,Completion Status,DIFFERENT,NOT DONE

Example 4: Using OR as a connector between conditions in the supporting document (use same group)

The report will output when Category is null for test TUMSTATE if Completion Status is different than Not Done OR if Completion Status is null

CRITERIA_FORM,CRITERIA_ITEMQUESTION,CRITERIA_VALUE,VENDOR,ITEMQUESTION,TEST SHORT NAME,GROUP1,CONDITEMQUESTION1,CONDSYMBOL1,CONDRESULT1,GROUP2,CONDITEMQUESTION2,CONDSYMBOL2,CONDRESULT2

NA,NA,NA,ICON,Category,TUMSTATE,1,Completion Status,DIFFERENT,NOT DONE,1,Completion Status,EQUAL,NULL

Example 5: Using AND as a connector between conditions in the supporting document (use different groups)

The report will output when Category is null for test TUMSTATE if Completion Status is different than Not Done AND if Location of Measurement is equal to Liver

CRITERIA_FORM,CRITERIA_ITEMQUESTION,CRITERIA_VALUE,VENDOR,ITEMQUESTION,TEST SHORT NAME,GROUP1,CONDITEMQUESTION1,CONDSYMBOL1,CONDRESULT1,GROUP2,CONDITEMQUESTION2,CONDSYMBOL2,CONDRESULT2

NA,NA,NA,ICON,Category,TUMSTATE,1,Completion Status,DIFFERENT,NOT DONE,2,Location of Measurement,EQUAL,Liver

Example 6: Using AND and OR at the same time as connectors between conditions in the supporting document

The report will output when Category is null for test TUMSTATE if (Completion Status is different than Not Done OR if Completion Status is NULL ) AND if Location of Measurement is equal to Liver (same group is used between the first 2 conditions and a different group is used for the third condition)

CRITERIA_FORM,CRITERIA_ITEMQUESTION,CRITERIA_VALUE,VENDOR,ITEMQUESTION,TEST SHORT NAME,GROUP1,CONDITEMQUESTION1,CONDSYMBOL1,CONDRESULT1,GROUP2,CONDITEMQUESTION2,CONDSYMBOL2, CONDRESULT2,GROUP3,CONDITEMQUESTION3,CONDSYMBOL3,CONDRESULT3

NA,NA,NA,ICON,Category,TUMSTATE,1,Completion Status,DIFFERENT,NOT DONE,1,Completion Status,EQUAL,NULL,2,Location of Measurement,EQUAL,Liver

Note to programmer: The first condition (if present) will always be “AND” with the main logic

Notefor CDMs: For Mega trials with large number records in datasets, usage of Parameters like Country , Site , Vendor , Test etc is mandatory and try to run per value in the case.
