2. LOGIC UNDERSTANDING
======================================================================
This spec identifies, per randomized subject and per lesion, missing LSN eCRF 'DATE OF LESION EVALUATION' records under two distinct scenarios: Logic 1/Table 1 (Scenario 1) checks for a missing evaluation within a day-window around a PMS1/PMST discontinuation visit for the subject's treatment phase, while Logic 2/Table 2 (Scenario 2) checks for missing evaluations against a series of periodically-calculated 'Expected Timeframe' windows (derived from Minimal start timepoint, Start/Stop week, and Frequency) once the system date has passed each timeframe. Both logics are heavily gated by supporting-document-defined parameters (windows, method of assessment, trial segment references) and suppressed by several competing real-world events (subsequent PMS1A/OEDRA assessments, new oncologic treatment/radiation/surgery starts, next-phase overlap, RNT records, lesion merge/split reclassification) that would explain away an apparently missing evaluation. Treatment-phase scoping (via LSN Date of Initial Identification vs. phase-specific Minimal start timepoints) and numerous NA/older-vs-newer-trial toggles (PMS1A vs OEDRA, presence of merge/split item, RNT applicability) must be resolved before the core Logic 1/Logic 2 boolean conditions can be evaluated correctly.

1. Before any Logic 1/2 processing, apply the subject-level eligibility filter: the subject's data must satisfy 'Criteria Form1'.'Criteria Itemquestion1' = 'Criteria Value1' AND the same for criteria 2 and 3, all values sourced from the supporting document -- only subjects meeting all three match conditions proceed to the report logic.
2. Logic 1 (drives Table 1 / Scenario 1): First confirm there exists a 'PMS Form' (PMS1/PMST, per Note 4) record with Trial Segment Reference equal to the 'Trial Segment Reference' value from the supporting document (Logic 1.1) -- this establishes the discontinuation/reference visit exists for that treatment phase.
3. Given that PMS Form record exists, check that there is NO LSN eCRF 'DATE OF LESION EVALUATION' among the LSN records belonging to that same treatment phase that falls within a qualifying window (Logic 1.2) -- i.e., we are looking for an absence of a valid evaluation date in the window.
4. The qualifying window is defined as: LSN 'DATE OF LESION EVALUATION' >= (PMS Form DOV - Lower window of days) (Logic 1.3) AND <= (PMS Form DOV + Upper window of days) (Logic 1.4, skipped entirely if Upper window of days = NA per Note 3).
5. Additionally, any candidate LSN evaluation within that window must match on 'Method of Assessment' equal to the value defined per the corresponding 'Group for Method' in the supporting document (Logic 1.5); if Group for Method and Method of Assessment are both NA, this check is skipped entirely (Note 39).
6. Logic 1 also requires (in parentheses, i.e., an additional AND block) that there is NOT a PMS1A record with the specified 'PMS1A Trial Segment Reference' and Date of Assessment <= (PMS Form DOV - Lower window of days) (Logic 1.6), AND there is NOT an OEDRA record with Date of Assessment <= that same threshold (Logic 1.7) -- these act as suppression checks so that if a later disease assessment already occurred before the window lower bound, no missing-evaluation flag is raised. Per Note 42, if the 'Cut-off Exclude Form' parameter names PMS1A (or OEDRA), the corresponding check (1.6 or 1.7) is skipped.
7. If Logic 1.1 through 1.7 are all satisfied (PMS visit exists, no matching lesion evaluation in window, no suppressing PMS1A/OEDRA assessment), the subject/lesion/visit combination is flagged as missing and output to Table 1. (inferred)
8. Logic 2 (drives Table 2 / Scenario 2) begins by requiring the current System date is greater than the 'Expected Timeframe' being evaluated (Logic 2.1) -- meaning the expected timeframe window has already fully elapsed (using the maximum/end date of the range per Note 26) before it can be flagged as missing.
9. Check that there is NOT at least one LSN record in the add-entry section where the LSN 'DATE OF LESION EVALUATION' falls within the 'Expected Timeframe' for that treatment phase (Logic 2.3) AND the LSN 'METHOD OF ASSESSMENT' matches the value defined for the corresponding 'Group for Method' (Logic 2.4, using the maximum date of the range per Note 26; skipped if Group for Method/Method of Assessment = NA per Note 39) -- combined this is Logic 2.2, the absence-of-a-valid-evaluation check for this timeframe.
10. An additional lesion-merge/split condition must hold (parenthesized OR block): either the LSN 'LESION NUMBER' is not referenced in any other record's 'INDICATE IF LESION MERGED OR SPLIT' field (Logic 2.5), OR it is referenced but the Expected Timeframe is before that record's 'DATE OF LESION EVALUATION' and the merge/split indicator is NULL (Logic 2.6 + 2.7), OR the merge/split indicator is NOT NULL and the missing evaluation date is after the LSN 'DATE OF INITIAL IDENTIFICATION' (Logic 2.8). Per Note 22, this entire merge/split sub-check is bypassed for older trials where the item doesn't exist.
11. Check that there is NOT at least one 'Oncologic Treatment' (ODBF) record where the Start Date of Regimen/Medication is not null and Expected Timeframe precedes the minimum such start date across all records (Logic 2.9, using minimum date of the range per Note 26) -- this suppresses the missing flag if a new oncologic treatment regimen started before the expected timeframe. Skipped entirely if 'Oncologic Treatment' = NA in supporting doc (Note 15).
12. Similarly check there is NOT at least one 'Oncologic Radiation' (ORAD2) record with a non-null Date where Reason is not Palliative, and Expected Timeframe precedes the minimum such ORAD2 date (Logic 2.10) -- suppresses flag if radiation treatment (non-palliative) started before the expected timeframe. Skipped if 'Oncologic Radiation' = NA (Note 16).
13. Similarly check there is NOT at least one 'Oncologic Surgery' (OSOF) record with a non-null Date of Surgery where Expected Timeframe precedes the minimum such surgery date (Logic 2.11) -- suppresses flag if surgery occurred before the expected timeframe. Skipped if 'Oncologic Surgery' = NA (Note 17).
14. Check the parenthesized OR block: there is NOT a PMS1A record (with the specified 'PMS1A Trial Segment Reference') with Date of Assessment <= Expected Timeframe (Logic 2.12), OR there is NOT an OEDRA record with Date of Assessment <= Expected Timeframe (Logic 2.13) -- using the maximum date of the timeframe range for 2.13 per Note 26, minimum for 2.12. This mirrors the Logic 1.6/1.7 suppression concept but applied against the Expected Timeframe rather than the PMS window. Skippable per Cut-off Exclude Form parameter (Note 42).
15. Check another parenthesized OR block regarding phase transition: either the subsequent treatment phase's 'Minimal start timepoint' (its DOV or Date of Assessment of SR) is NULL (Logic 2.14, meaning no next phase has started yet), OR the current 'Expected Timeframe' is still less than that subsequent phase's Minimal start timepoint (Logic 2.15) -- this prevents flagging a missing evaluation for phase X if the Expected Timeframe actually falls into or after the next phase's start (consistent with Note 27's overlap rule).
16. Finally, check there is NOT at least one RNT record with RNT.Date of Assessment not null (Logic 2.16) -- another suppression check, applicable only to newer trials since RNT is not implemented in old trials (Note 41).
17. If Logic 2.1 through 2.16 are all satisfied simultaneously (timeframe elapsed, no matching evaluation found, no merge/split disqualification, no earlier oncologic treatment/radiation/surgery start, no earlier PMS1A/OEDRA assessment, no next-phase overlap, no RNT record), that specific Expected Timeframe/lesion combination is flagged as missing and output to Table 2. (inferred)
18. Before applying Logic 1 or Logic 2, treatment phases must first be delineated per Note 30 using LSN 'DATE OF INITIAL IDENTIFICATION' compared against each phase's 'Minimal start timepoint' (e.g., Cycle 1, Second Course Cycle 1) combined with Tumor Identification conditions (target/non-target vs new lesion) and presence/absence of the merge/split indicator -- this scoping determines which LSN records 'belong to the corresponding treatment phase' referenced throughout Logic 1.2 and Logic 2.3/2.9-2.16. (inferred)
19. The 'Expected Timeframe' values used throughout Logic 2 (and referenced in Table 1 column 9/Table 2 column 10) are pre-calculated per Note 25's stepwise formula: compute Timepoint N = Minimal start timepoint + Start week + (N-1)*Frequency for each N, retain only those Timepoints between (Minimal start timepoint + Start week) and (Minimal start timepoint + Stop week), then expand each retained Timepoint by Lower/Upper window of days to form the displayed range 'From X to Y'.
20. Special handling per Note 24 overrides both Logic 1 and Logic 2 outputs: even if all other conditions are met, do not output a missing evaluation if the Expected Timeframe (or window) falls before the LSN 'DATE OF INITIAL IDENTIFICATION' for that lesion, since Expected Timeframe should always logically follow initial identification (accounts for lesions newly identified after cycle 1).

3. SPEC REVIEW
======================================================================
