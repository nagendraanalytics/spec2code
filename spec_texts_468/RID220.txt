Report ID: RID220

Report Title:
Missing Modules per Cohort or Arm

Description:
This report displays all missing required modules and the not required but completed modules per Cohort or Arm.  Any queries and comments written on the DOV.

Column Heading:
1. Country

2. Site

3. Subject Number

4. Criteria 1

5. Criteria 2

6. Criteria 3

7. Visit Mnemonic

8. Date of Visit

9. eCRF Name

10. Useful Message

11. Query Status

12. Queries on DOV

13. Comments on DOV

14. Scenario

Logic:
<Criteria Form1>.<Criteria Itemquestion1> = <Criteria Value1>  AND

<Criteria Form2>.<Criteria Itemquestion2> = <Criteria Value2> AND

<Criteria Form3>.<Criteria Itemquestion3> = <Criteria Value3> AND

Scenario 1: Missing forms

Display eCRF name for all Visits that have started and the required form per supporting document has not been Started (Forms.Started = 0 or Forms.Started is null).

Display in scenario: Missing Form

Scenario 2: Incorrect forms:

Display eCRF name for all Visits that have started and a NOT required form per supporting document has been Started (Forms.Started <> null).

Display in scenario: Incorrect Form

Notes:

1. For visits with Date of Visit field, the DOV will be considered as initializer of the visit. For visits with no DOV and the common form group, any form within that visit/group may be considered as initializer.

2. If Erroneous Visit was checked for a subject, remove the output for that subject's visit from the report. Also display any queries and comments written on the DOV or UNS.

3. The report should have parameter selections for the Forms and Visits, as well as for the Gender The Hide Queries & Comments prompt hides the three last columns and shows distinct forms by subject and visit.

4. The Window for DOV prompt (in days) allows for the retrieval of forms only if (the corresponding DOV + Window for DOV) < the date of report running. Common forms will be shown independently of the Window for DOV.

5. The username will be included in the footer.

The output will be dependent on the user who is logged in. The output will only show the data related to the fields that are not hidden to the user.

6. For scenario 1: Report should display message when all the records are deleted or completed as Not Done/Not Applicable/Unknown  “ Repeating form with all records deleted or completed with radio button”.

7. For scenario 1: Report should display message when all the items are deleted or completed as Not Done/Not Applicable/Unknown  “ Flat form with all items deleted or completed with radio button”.

8. For scenario 2: When all the items are deleted or completed as Not Done/Not Applicable/Unknown output should not be considered.

9. For scenario 1: When at least 1 record is present, form should not be on the output.

10. If "Randomized only" parameter selection checkbox is checked, the report should only output subjects with Randomization number that is not null.

11. For scenario 1, forms that are required per supporting document but are not triggered yet in a specific visit should also be considered and should generate output if missing.

The parameters “Supporting Document Start Point” and “Supporting Document End Point” must be completed with the first and the last row from supporting document to include in the run, respectively, when the supporting document has more than 1500 rows. If so, the report will be run per groups (e.g., 1 to 1500 rows (run 1), 1501 to 3000 (run 2)). If supporting document has less than 1500 rows, the report will be run with the default values (i.e., “Supporting Document Start Point”: 1 and “Supporting Document End Point”: 1500) as parameters cannot remain blank.

The number of rows in the supporting document will be represented in the Report Header as "# of rows for customization".

The actual information provided by the supporting doc can be outputted by selecting Y in the parameter "Supporting doc Page".

Report Scenarios:
Scenario 1:

Output = Yes. Which satisfies logic (eCRF is blank or records are deleted or completed as Not Done/Not Applicable/Unknown for specific visit for subject in specific Arm/Cohort/Stratification)

Output = No. Which doesn’t satisfies logic (eCRF has record(s) for specific visit for subject in specific Arm/Cohort/Stratification)

Scenario 2:

Output = Yes.

When as per scenario 2 logic, eCRF is completed in an initialized visit but eCRF is not required for specific visit for subject in specific Arm/Cohort/Stratification per supporting document

Output = No. When eCRF is null or is acceptable for specific visit for subject in specific Arm/Cohort/Stratification per supporting document
