Description:
This report identifies Procedure overlaps based on matching PT/LLT terms and overlapping onset/end dates. (Report Title: Procedures Overlapping with same subject for same PT/LLTs)

Column Heading:
1. Country
2. Site
3. Subject Number
4. Form
5. Encoding Hierarchy
6. PROC Encoded Term
7. PROC 1 Seq (PROC 1 is the one with smaller Seq. No. between the pair of overlapping records)
8. PROC 1 Verbatim
9. PROC 1 Start Date
10. PROC 1 Stop Date
11. PROC 2 Seq (PROC 2 is the one with bigger Seq. No. between the pair of overlapping records)
12. PROC 2 Verbatim
13. PROC 2 Start Date
14. PROC 2 Stop Date

Logic:
Output is produced if a subject has overlapping Procedure Start Date and Procedure Stop Date for identical Procedure PT or LLT Terms. Each pair of overlapping Procedures should be output on one line.

User should select PT or LLT for comparison in parameter. If nothing is selected, output for overlapping identical LLT or PT.

Partial date also need to be considered while programming for identifying overlapping records

If either of the PROC has blank onset date or end date, consider them as ongoing.

If Procedure Start Date has UNK, please convert to the first day of the month and/or Jan;

If Procedure Stop Date has UNK, please convert to the last day of the month and /or Dec.

Deleted record and erroneous visits should not be considered.

For APPRC consider taking start date as stop date, since stop date is not available on form

Report Scenarios:
Please check two forms: PROC and APPRC. Check within form only.

a. If parameter LLT is selected:

1) Output = YES
two identical Procedure terms (with same LLT after encoding) have overlapping start dates/end dates

2) Output = NO
identical Procedure terms (with same LLT after encoding) have no overlapping start dates/end dates

3) Output = NO
different Procedure terms (with different LLT after encoding)

4) Output = NO
Deleted PROC record

b. If parameter PT is selected, or no selection with PT/LLT or both selected:

1) Output = YES
two identical Procedure terms (with same PT and same LLT after encoding) have overlapping start dates/end dates

2) Output = YES
two identical Procedure terms (with same PT and different LLT after encoding) have overlapping start dates/end dates

3) Output = NO
identical Procedure terms (with same PT after encoding) have no overlapping start dates/end dates

4) Output = NO
different Procedure terms (with different PT after encoding)

5) Output = NO
Deleted PROC record

Sorting:
Country, Site, Subject Number, PROC 1 Seq

2. LOGIC UNDERSTANDING
======================================================================
This spec identifies pairs of Procedure records (within the PROC form, and separately within the APPRC form) for the same subject where the encoded term (LLT or PT, per user parameter selection) matches and the Start/Stop date ranges overlap, after applying date-cleaning rules for UNK values, partial dates, ongoing (blank date) records, and the APPRC-specific substitution of Start Date for the missing Stop Date. Matching criteria differ depending on whether LLT or PT (or default/both) is selected as the comparison parameter, with PT-level matching being more permissive (allowing different LLTs) than LLT-level matching. Each qualifying overlapping pair is output as one row, with the earlier-Seq record labeled PROC 1 and the later-Seq record PROC 2, sorted by Country, Site, Subject Number, and PROC 1 Seq, while deleted records and erroneous visits are excluded upfront.

1. Identify all Procedure records for a subject from the PROC form (and separately, from the APPRC form) - these two forms are checked independently of each other, per 'Please check two forms: PROC and APPRC. Check within form only.'
2. Exclude any deleted records and records tied to erroneous visits from consideration entirely, per 'Deleted record and erroneous visits should not be considered' and the scenario rule that Deleted PROC record always yields Output = NO.
3. For each subject, determine the comparison level (LLT or PT) based on the user-selected parameter: if LLT is selected, compare using the encoded LLT term; if PT is selected, or if no selection is made, or if both PT and LLT are selected, compare using the encoded PT term (per Report Scenarios section b heading covering 'no selection with PT/LLT or both selected'). (inferred)
4. Apply date-cleaning rules before comparing ranges: if Start Date contains UNK, convert the unknown day to the first day of the month and/or unknown month to January; if Stop Date contains UNK, convert unknown day to the last day of the month and/or unknown month to December.
5. If either record in a potential pair has a blank onset (start) date or blank end (stop) date, treat that record as ongoing (open-ended) for the purpose of the overlap check.
6. For APPRC records specifically, since there is no Stop Date field on that form, use the Start Date value as a substitute for the Stop Date when computing date ranges.
7. Account for partial (incomplete) dates generally when determining whether two date ranges overlap, per 'Partial date also need to be considered while programming for identifying overlapping records.'
8. Compare pairs of Procedure records within the same subject (and within the same form) to see whether their Start Date-to-Stop Date ranges overlap (intersect) in time.
9. If parameter LLT is selected: output YES only when two Procedure records share the same encoded LLT term AND their date ranges overlap; if the LLT terms differ, or if LLT terms match but dates do not overlap, output NO (per scenario a.1-a.3).
10. If parameter PT is selected (or no selection, or both PT/LLT selected): output YES when two records share the same encoded PT term and their dates overlap, regardless of whether the LLT terms are the same or different (per scenario b.1 and b.2); output NO if the PT terms match but dates don't overlap, or if PT terms differ entirely (per scenario b.3-b.4).
11. For each identified overlapping pair meeting the matching criteria, designate the record with the smaller Seq. No. as PROC 1 and the record with the larger Seq. No. as PROC 2.
12. Output one line per overlapping pair, including Country, Site, Subject Number, Form, Encoding Hierarchy, PROC Encoded Term, and the Seq/Verbatim/Start Date/Stop Date details for both PROC 1 and PROC 2.
13. Sort the final output by Country, Site, Subject Number, and PROC 1 Seq.

SELECT
  p1.SiteCountry AS `Country`,
  p1.SiteNumber AS `Site`,
  p1.SubjName AS `Subject Number`,
  p1.FormName AS `Form`,
  (CASE
     WHEN @LLTPT = 'LLT' THEN 'LLT'
     WHEN @LLTPT = 'PT' THEN 'PT'
     ELSE 'PT&LLT'
   END) AS `Encoding Hierarchy`,
  p1.EncodedTerm AS `PROC Encoded Term`,
  p1.Seq AS `PROC 1 Seq`,
  p1.Verbatim AS `PROC 1 Verbatim`,
  p1.StartDate AS `PROC 1 Start Date`,
  p1.StopDate AS `PROC 1 Stop Date`,
  p2.Seq AS `PROC 2 Seq`,
  p2.Verbatim AS `PROC 2 Verbatim`,
  p2.StartDate AS `PROC 2 Start Date`,
  p2.StopDate AS `PROC 2 Stop Date`
FROM
  (
    SELECT `@HDR`.`Subject`.`ID` AS SubjID,
      `@HDR`.`Site`.`Country` AS SiteCountry,
      `@HDR`.`Site`.`Number` AS SiteNumber,
      `@HDR`.`Subject`.`Name` AS SubjName,
      `@Form`.`Name` AS FormName,
      PROCPRAESEQIT AS Seq,
      PROCPRPROTRMIT AS Verbatim,
      CODEDTERM(PROCPRPROTRMIT, 'PT') AS PTTerm,
      CODEDTERM(PROCPRPROTRMIT, 'LLT') AS LLTTerm,
      (CASE
         WHEN @LLTPT = 'LLT' THEN CODEDTERM(PROCPRPROTRMIT, 'LLT')
         WHEN @LLTPT = 'PT' THEN CODEDTERM(PROCPRPROTRMIT, 'PT')
         ELSE CONCAT(CODEDTERM(PROCPRPROTRMIT, 'PT'), '/', CODEDTERM(PROCPRPROTRMIT, 'LLT'))
       END) AS EncodedTerm,
      RAWDATE(PROCPRPRSTDTCIT) AS StartDate,
      RAWDATE(PROCPRPRENDTCIT) AS StopDate
    FROM `EDC`.`PROCFM`
    WHERE `@Form`.`Status` = 'submitted__v'
      AND (DELETEDFM = 'N' OR DELETEDFM IS NULL)
    UNION ALL
    SELECT `@HDR`.`Subject`.`ID` AS SubjID,
      `@HDR`.`Site`.`Country` AS SiteCountry,
      `@HDR`.`Site`.`Number` AS SiteNumber,
      `@HDR`.`Subject`.`Name` AS SubjName,
      `@Form`.`Name` AS FormName,
      ORAD2SEQNUMIT AS Seq,
      ORAD2PRTRTIT AS Verbatim,
      CODEDTERM(ORAD2PRTRTIT, 'PT') AS PTTerm,
      CODEDTERM(ORAD2PRTRTIT, 'LLT') AS LLTTerm,
      (CASE
         WHEN @LLTPT = 'LLT' THEN CODEDTERM(ORAD2PRTRTIT, 'LLT')
         WHEN @LLTPT = 'PT' THEN CODEDTERM(ORAD2PRTRTIT, 'PT')
         ELSE CONCAT(CODEDTERM(ORAD2PRTRTIT, 'PT'), '/', CODEDTERM(ORAD2PRTRTIT, 'LLT'))
       END) AS EncodedTerm,
      RAWDATE(ORAD2PRSTDTCIT) AS StartDate,
      RAWDATE(ORAD2PRSTDTCIT) AS StopDate
    FROM `EDC`.`ORAD2FM`
    WHERE `@Form`.`Status` = 'submitted__v'
      AND (DELETEDFM = 'N' OR DELETEDFM IS NULL)
  ) p1
  JOIN
  (
    SELECT `@HDR`.`Subject`.`ID` AS SubjID,
      `@HDR`.`Site`.`Country` AS SiteCountry,
      `@HDR`.`Site`.`Number` AS SiteNumber,
      `@HDR`.`Subject`.`Name` AS SubjName,
      `@Form`.`Name` AS FormName,
      PROCPRAESEQIT AS Seq,
      PROCPRPROTRMIT AS Verbatim,
      CODEDTERM(PROCPRPROTRMIT, 'PT') AS PTTerm,
      CODEDTERM(PROCPRPROTRMIT, 'LLT') AS LLTTerm,
      RAWDATE(PROCPRPRSTDTCIT) AS StartDate,
      RAWDATE(PROCPRPRENDTCIT) AS StopDate
    FROM `EDC`.`PROCFM`
    WHERE `@Form`.`Status` = 'submitted__v'
      AND (DELETEDFM = 'N' OR DELETEDFM IS NULL)
    UNION ALL
    SELECT `@HDR`.`Subject`.`ID` AS SubjID,
      `@HDR`.`Site`.`Country` AS SiteCountry,
      `@HDR`.`Site`.`Number` AS SiteNumber,
      `@HDR`.`Subject`.`Name` AS SubjName,
      `@Form`.`Name` AS FormName,
      ORAD2SEQNUMIT AS Seq,
      ORAD2PRTRTIT AS Verbatim,
      CODEDTERM(ORAD2PRTRTIT, 'PT') AS PTTerm,
      CODEDTERM(ORAD2PRTRTIT, 'LLT') AS LLTTerm,
      RAWDATE(ORAD2PRSTDTCIT) AS StartDate,
      RAWDATE(ORAD2PRSTDTCIT) AS StopDate
    FROM `EDC`.`ORAD2FM`
    WHERE `@Form`.`Status` = 'submitted__v'
      AND (DELETEDFM = 'N' OR DELETEDFM IS NULL)
  ) p2
  ON p1.SubjID = p2.SubjID
  AND p1.FormName = p2.FormName
  AND p1.Seq < p2.Seq
WHERE
  (
    (@LLTPT = 'LLT' AND p1.LLTTerm = p2.LLTTerm)
    OR
    (@LLTPT <> 'LLT' AND p1.PTTerm = p2.PTTerm)
  )
  AND p1.StartDate <= IFNULL(p2.StopDate, p1.StartDate)
  AND p2.StartDate <= IFNULL(p1.StopDate, p2.StartDate)
ORDER BY `Country`, `Site`, `Subject Number`, `PROC 1 Seq`
