Report ID:
ONC_PMS1_001_JR_STD

EDC System / Language:
veeva / CQL

Description:
Identifies subjects whose Status form (e.g., PMS1/PMS1A/PMST/OEDRA) indicates a reason for treatment discontinuation equivalent to "starting new (non-study) anti-cancer therapy" or "excluded medication discontinuation criteria" (as defined per-study in an external supporting document), but for whom no corresponding new anti-cancer therapy form (e.g., ORAD2, OSOF, OSOFL, ODBF, ODBHF, ODBNF, ODBCF - whichever are active in the protocol) exists with a non-palliative reason recorded. The report flags a data-consistency gap: therapy discontinuation was reported as due to new anti-cancer therapy, but no therapy-form record substantiates it (other than purely palliative/symptom-control radiation records, which are excluded from consideration as substantiating evidence). Source data: clinical trial subject/visit/status ("disposition/status") forms and oncology anti-cancer therapy forms (radiation, surgery, other treatment forms) drawn from an Oracle clinical data warehouse (subject registry, visit/date-of-visit form, and a data dictionary describing form/item/column mappings), combined with a study-specific supporting CSV document that defines which status form + item/question + status value combinations count as "new anti-cancer therapy discontinuation reasons" for that particular protocol.

Column Heading:
Country | Site | Subject Number | Visit | Form | Date of assessment | Status (with a possible second output page listing supporting-document contents: Status form | Itemmnemonic | Reason for Discontinuation)

Logic:
1. Verify a study-specific supporting document (ONC_PMS1_001_supp_<protocol>.csv) exists; if not, output only a message page stating the supporting document is not present for the trial. 2. If present, read the supporting doc, which lists, per study, the combinations of Status Form (PMS1/PMS1A/PMST/OEDRA), Itemmnemonic (the question capturing reason for study completion/discontinuation), and Reason for Discontinuation value that represent "subject is receiving a new anti-cancer therapy." 3. Pull subject/site/screening reference data and a visit-level "date of visit" form (excluding visits flagged with a visit-level error). 4. Pull data-dictionary metadata to dynamically identify, for each configured status form, the database view/column holding the status value and (if present) an assessment date column, filtered to forms PMS1FM/PMS1AFM/PMSTFM/OEDRAFM and specific item codes representing "status of study medication" or "status of subject" at end of segment. 5. Similarly identify, for each of the possible new anti-cancer therapy forms present in the protocol (ORAD2, OSOF, OSOFL, ODBF, ODBHF, ODBNF, ODBCF), the columns holding a form index, a deleted-form flag, and (for ORAD2 only) a "reason" field. 6. For each configured status-form view, extract subject-level status records and inner-join them to the supporting document on matching Form + Itemmnemonic/Itemquestion + Status value (case-insensitive, trimmed) -- these are the "candidate discontinuation-due-to-new-therapy" records, accumulated into one dataset (PMS). 7. For each configured therapy-form view, extract subject-level records, excluding logically deleted forms (deletedform = 'Y'), and excluding records whose reason begins with "PALLIATIVE" (palliative/symptom-control treatment reasons do not count as evidence of active new anti-cancer therapy) -- accumulated into one dataset (ODB). 8. Build the final candidate population: status-form records (from step 6) joined to the visit/date-of-visit dataset on subject+visit (to pick up assessment date and exclude visits with a visit-error flag), restricted to subjects who have NO matching record at all in the therapy dataset (ODB) built in step 7 -- i.e., no non-palliative anti-cancer therapy form evidence exists for that subject. This requires at least one anti-cancer therapy form type to be configured/applicable in the protocol. 9. Restrict to the relevant analysis subject subset via a standard subdataset/population filter macro. 10. Merge in subject demographic/site identifiers (country, site number, subject number) keeping only matched records. 11. Deduplicate on country/site/subject/visit/visit-mnemonic/form/date/status. 12. Output the final listing sorted by subject; if zero qualifying records, output a "No records meet the test condition" message instead of the listing. 13. Optionally (if a report parameter Supporting doc Page = Y) output a second report page listing the raw contents of the supporting document, with the row count shown in the report header/title as "# of rows for Supporting Doc."

Report Scenarios:
Scenario A: Supporting document for the trial does not exist -- output a single message page: "ONC_PMS1_001_JR_STD Supporting Document Not Present for This Trial" plus guidance to check the DRP/contact programmer. Scenario B: Supporting document exists but the final filtered dataset has zero qualifying subject records -- output "No records meet the test condition" message page (titles still show supporting-doc row count and supporting-doc-page parameter value). Scenario C: Supporting document exists and qualifying records are found -- output the full listing report (Country/Site/Subject/Visit/Form/Date of assessment/Status). Scenario D: Special business rule -- when ORAD2 is the only applicable anti-cancer therapy eCRF completed for a subject (all other therapy forms OSOF, ODBF, ODBHF, ODBNF, ODBCF empty) and ALL of that subject's ORAD2 "reason" entries indicate palliative treatment/symptom control (or palliative treatment/symptom control of metastatic disease), the subject IS still output as a discrepancy (no substantiating non-palliative therapy exists); but if even one ORAD2 reason record is non-palliative, the subject is NOT output (a valid non-palliative therapy record exists). Scenario E (optional add-on, controlled by a parameter): output an additional page listing the raw supporting-document rows (Status form/Itemmnemonic/Reason for Discontinuation) when the "Supporting doc Page" parameter = Y.

Sorting:
Final listing is deduplicated and effectively ordered by Country, Site number, Subject number, Visit ID, Visit mnemonic, Form mnemonic, Date of assessment, Status (via PROC SORT NODUPKEY on final dataset by these keys); intermediate final dataset (finalini) is sorted by subjectid before merging with subject demographics. Supporting-document listing page has no explicit sort (row order as read from CSV).

2. LOGIC UNDERSTANDING
======================================================================
This report cross-references oncology Status forms (PMS1/PMS1A/PMST/OEDRA) against a study-specific external supporting CSV to identify which discontinuation reasons mean 'switched to new anti-cancer therapy,' then checks whether any corresponding, non-deleted, non-palliative anti-cancer therapy form (ORAD2/OSOF/OSOFL/ODBF/ODBHF/ODBNF/ODBCF) exists for that subject as substantiating evidence. If a subject's status record matches a 'new therapy' discontinuation reason but has zero substantiating non-palliative therapy records (evaluated per-record, so even one non-palliative ORAD2 reason clears the subject per Scenario D), the subject is flagged as a data-consistency gap and listed in the final output, subject to the existence of the supporting document, population filtering, demographic matching, and deduplication."

SELECT
  PMS_D.Country AS `Country`,
  PMS_D.Site AS `Site`,
  PMS_D.SubjectNumber AS `Subject Number`,
  PMS_D.Visit AS `Visit`,
  PMS_D.StatusForm AS `Form`,
  DATE_FORMAT(PMS_D.AssessDateRaw, '%d%b%Y') AS `Date of assessment`,
  PMS_D.StatusValue AS `Status`
FROM
(

-- Candidate discontinuation-due-to-new-therapy records from PMS1/PMS1A/PMST status forms,
  -- joined to visit/date-of-visit data (excluding erroneous visits) for assessment date.
  -- NOTE: the supporting-doc-driven Form+Itemmnemonic+Status combinations (step 6) cannot be
  -- enumerated here since the external CSV content is not available; PMS1FM.PMS1DSTERMSTATIT
  -- and PMS1DSDTCIT are used as the status/date items per study metadata, and the status value
  -- filter below is a placeholder representing "matches supporting-doc value list."
SELECT
    `@HDR`.`Subject`.`ID` AS SubjectID,
    `@HDR`.`Site`.`Country` AS Country,
    `@HDR`.`Site`.`Number` AS Site,
    `@HDR`.`Subject`.`Name` AS SubjectNumber,
    DOV_M.VisitMnemonic AS Visit,
    `@Form`.`Name` AS StatusForm,
    DOV_M.VisitDateRaw AS AssessDateRaw,
    PMS1FM.PMS1DSTERMSTATIT AS StatusValue
  FROM `EDC`.`PMS1FM` PMS1FM
  INNER JOIN
  (
    SELECT
      `@HDR`.`Subject`.`ID` AS SubjectID,
      `@HDR`.`Event`.`Name` AS VisitMnemonic,
      RAWDATE(DOVFM.DOV) AS VisitDateRaw
    FROM `EDC`.`DOVFM` DOVFM
    WHERE `@Form`.`Status` = 'submitted__v'
      AND (DOVFM.DOVSERRORVIT = 'N' OR DOVFM.DOVSERRORVIT IS NULL)
  ) DOV_M
    ON `@HDR`.`Subject`.`ID` = DOV_M.SubjectID
  WHERE `@Form`.`Status` = 'submitted__v'

-- Supporting-doc match placeholder: status value indicating "new anti-cancer therapy" or
    -- "excluded medication discontinuation criteria" per ONC_PMS1_001_supp_<protocol>.csv
    AND PMS1FM.PMS1DSTERMSTATIT IN ('New Anti-Cancer Therapy', 'Excluded Medication Discontinuation Criteria')

  UNION ALL
SELECT
    `@HDR`.`Subject`.`ID` AS SubjectID,
    `@HDR`.`Site`.`Country` AS Country,
    `@HDR`.`Site`.`Number` AS Site,
    `@HDR`.`Subject`.`Name` AS SubjectNumber,
    DOV_M2.VisitMnemonic AS Visit,
    `@Form`.`Name` AS StatusForm,
    DOV_M2.VisitDateRaw AS AssessDateRaw,
    OEDRAFM.OEDRATERMSUBDCRC AS StatusValue
  FROM `EDC`.`OEDRAFM` OEDRAFM
  INNER JOIN
  (
    SELECT
      `@HDR`.`Subject`.`ID` AS SubjectID,
      `@HDR`.`Event`.`Name` AS VisitMnemonic,
      RAWDATE(DOVFM.DOV) AS VisitDateRaw
    FROM `EDC`.`DOVFM` DOVFM
    WHERE `@Form`.`Status` = 'submitted__v'
      AND (DOVFM.DOVSERRORVIT = 'N' OR DOVFM.DOVSERRORVIT IS NULL)
  ) DOV_M2
    ON `@HDR`.`Subject`.`ID` = DOV_M2.SubjectID
  WHERE `@Form`.`Status` = 'submitted__v'
    AND OEDRAFM.OEDRATERMSUBDCRC IN ('New Anti-Cancer Therapy', 'Excluded Medication Discontinuation Criteria')
) PMS_D
WHERE NOT EXISTS (

-- ORAD2: radiation therapy records, excluding deleted forms and palliative reasons
SELECT 1 FROM `EDC`.`ORAD2FM` ORAD2FM
  WHERE `@HDR`.`Subject`.`ID` = PMS_D.SubjectID
    AND `@Form`.`Status` = 'submitted__v'
    AND (ORAD2FM.DELETEDFM = 'N' OR ORAD2FM.DELETEDFM IS NULL)
    AND (ORAD2FM.ORAD2PRINDCIT IS NULL OR UPPER(TRIM(ORAD2FM.ORAD2PRINDCIT)) NOT LIKE 'PALLIATIVE%')
)
AND NOT EXISTS (

-- OSOF: surgery/other treatment records, excluding deleted forms
SELECT 1 FROM `EDC`.`OSOFFM` OSOFFM
  WHERE `@HDR`.`Subject`.`ID` = PMS_D.SubjectID
    AND `@Form`.`Status` = 'submitted__v'
    AND (OSOFFM.DELETEDFM = 'N' OR OSOFFM.DELETEDFM IS NULL)
)
AND NOT EXISTS (

-- ODBHF: oncologic treatment/regimen records, excluding deleted forms
SELECT 1 FROM `EDC`.`ODBHFFM` ODBHFFM
  WHERE `@HDR`.`Subject`.`ID` = PMS_D.SubjectID
    AND `@Form`.`Status` = 'submitted__v'
    AND (ODBHFFM.DELETEDFM = 'N' OR ODBHFFM.DELETEDFM IS NULL)
)
ORDER BY
  `Country`, `Site`, `Subject Number`, `Visit`, `Form`, `Date of assessment`, `Status`

Explanation:
I built the "candidate discontinuation" dataset (PMS) from the two status forms confirmed in the study metadata that carry a discontinuation-reason/status item and a date item (PMS1FM.PMS1DSTERMSTATIT/PMS1DSDTCIT and OEDRAFM.OEDRATERMSUBDCRC/OEDRADSDTCIT) -- PMS1A/PMST were mentioned in the spec but no matching Form was present in the provided metadata, so they are omitted and flagged here as a gap; the exact qualifying status VALUES are supposed to come from the external ONC_PMS1_001_supp CSV (which isn't accessible to this engine), so I used illustrative placeholder literals ('New Anti-Cancer Therapy'/'Excluded Medication Discontinuation Criteria') that must be replaced with the real values from that document. Each status record is joined to DOVFM (excluding erroneous visits, DOVSERRORVIT) for the assessment date/visit. The "no substantiating therapy" check (steps 7-8, including the ORAD2-only/palliative Scenario D rule) is implemented as three correlated NOT EXISTS subqueries against the therapy forms actually present in metadata (ORAD2FM, OSOFFM, ODBHFFM -- OSOFL/ODBF/ODBNF/ODBCF were not found in the metadata list and are therefore omitted/flagged), excluding deleted forms (DELETEDFM='N' or NULL) and, for ORAD2 only, excluding reasons beginning with "PALLIATIVE" per the spec's non-palliative-evidence rule; this NOT EXISTS structure naturally implements Scenario D since a subject is only excluded from output if at least one non-palliative ORAD2 record (or any OSOF/ODBHF record) exists. This query omits the supporting-document-existence check, the "Supporting doc Page" second output, and zero-result message handling since those are report-runtime/presentation logic outside CQL's SELECT scope -- these should be handled at the report-template layer, and the supporting-doc CSV content and item/status mappings should be confirmed via DESCRIBE FORM and the real supporting document before running.
