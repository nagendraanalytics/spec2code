2. LOGIC UNDERSTANDING
======================================================================
This report identifies subjects where DS01 disposition data and PMS1/PMST protocol milestone data are inconsistent, using a supporting document to map Subject Status/Medication Status types to specific PMSf forms, PMSv visits, and SM Forms. Three independent logic branches check for: (1) a disposition status + first-dose SM record existing but no corresponding populated PMS status item at the configured visit ('Missing'), (2) both disposition status/date and a completed PMS assessment existing but the PMS assessment date falling after the disposition date ('Mismatch'), and (3) PMS indicating the subject is not continuing to the next segment while DS01 has no disposition status recorded ('DS01 Status missing'). Deleted records, Erroneous Visits, and Screen Failure subjects are excluded throughout, and results are sorted by Country/Site/Subject Number.

1. This report compares DS01 (disposition) records against PMS1/PMST (Protocol Milestone Status) and SM/SMAU/SMAB/SM01 (Study Medication) records to find three types of mismatches, driven by a supporting document (DS004_supp_<xxxxxxx>.csv) that maps each 'Status' type (Subject Status or Medication Status) to a specific PMSf form, PMSv visit, and SM Form.
2. Logic 1 (Subject Status Missing/Medication Status Missing): First check that DS01.'Select the Status of the Subject for the Study' is not null (Logic 1.1) - meaning the subject has a disposition status recorded.
3. Also for Logic 1, check that the 'SM Form' (as defined per supporting doc row, e.g. SM, SMAU, SMAB, or SM01) has a Start Date that is not null (Logic 1.2), and that on that same SM Form record, 'Please Indicate if this is the First Dose for this Label Description' = 'First Dose' (Logic 1.3) - identifying the record marking the subject's first dose of medication.
4. Given Logic 1.1-1.3 are true (disposition status exists AND a first-dose SM record exists), the report then checks whether there is NO corresponding PMS record satisfying: 'PMSf'.'PMS Itemquestion' is not null (Logic 1.4) AND 'PMSf'.visitmnemonic = 'PMSv' (Logic 1.5) - i.e., no PMS record at the configured visit has the relevant Status-of-Subject/Medication-at-End-of-Segment item populated.
5. If Logic 1.1-1.3 are true but no matching PMS record per Logic 1.4/1.5 exists, the subject is flagged with a missing status error - displayed in column 10 as 'Subject Status Missing' or 'Medication Status Missing' depending on the supporting doc's Status value for that row.
6. Logic 2 (Subject Status Mismatch/Medication Status Mismatch): Check that DS01.'Select the Status of the Subject for the Study' is not null (Logic 2.1) AND DS01.'Date of Disposition' is not null (Logic 2.2) - the subject has both a disposition status and a disposition date recorded.
7. Also for Logic 2, require that a PMS record exists at the configured visit ('PMSf'.visitmnemonic = 'PMSv', Logic 2.4) where 'PMSf'.Date of Assessment is not null (Logic 2.3) and 'PMSf'.'PMS Itemquestion' is not null (Logic 2.5) - i.e., there IS a completed PMS record with the status item populated, unlike Logic 1 where it was absent.
8. Logic 2 flags a mismatch when, despite that PMS record existing, its Date of Assessment is AFTER the DS01 Date of Disposition (Logic 2.6: 'PMSf'.Date of Assessment > DS01.Date of Disposition) - meaning the PMS assessment was recorded later than the disposition date, which is considered an inconsistency/mismatch in timing.
9. When Logic 2.1-2.6 all hold true, the subject is flagged with a mismatch error - displayed in column 10 as 'Subject Status Mismatch' or 'Medication Status Mismatch' depending on the supporting doc's Status value for that row.
10. Logic 3 (DS01 Status missing): Check if 'PMSf'.'Select the Status of the Subject for the Next Trial Segment' is like 'Not Continuing%' (Logic 3.1) - meaning the PMS form indicates the subject is not continuing into the next trial segment.
11. If Logic 3.1 is true AND DS01.'Select the Status of the Subject for the Study' is null (Logic 3.2), the subject is flagged - i.e., PMS indicates the subject stopped continuing but DS01 has no corresponding disposition status recorded, displayed in column 10 as 'DS01 Status missing'.
12. Across all three logic branches, records must exclude deleted records and Erroneous Visits (Note 4), and must exclude subjects whose DS01 form Status = 'Screen failure' (Note 5), since screen failures are not expected to follow the normal disposition/PMS pairing.
13. The supporting document drives which PMSf/PMSv/SM Form combinations are checked per Status type; each row in the supporting doc is treated as a separate rule to evaluate against subject data, and a subject may be evaluated against multiple rows (e.g., both 'Follow-up Day 30' and 'Follow-up 1' visits for Subject Status), inferred since the example shows multiple rows sharing the same Status but different PMSv/SM Form values. (inferred)
14. When the 'SM Form' column in the supporting doc lists multiple values separated by '|' (e.g., SM|SMAB), the SM Form conditions in Logic 1.2/1.3 are checked globally across all listed forms (i.e., satisfied if any of the listed forms has a matching first-dose record with non-null Start Date), per Note 7.4.
15. Output is only generated for subjects/visit combinations that meet the criteria of Logic 1, 2, or 3; if none of the three logic branches trigger for a subject, no row is output for that subject (per Report Scenarios note).
16. Final report rows are sorted by Country, Site, Subject Number, and columns are populated per the Column Heading list including Visit, Study Treatment Form, First Dose Date, PMS1 form, PMS1 Date of Assessment, DS01 Date, DS01 Status (the error type text), and Error Message.

SELECT
  d.Country AS `Country`,
  d.Site AS `Site`,
  d.SubjectNumber AS `Subject Number`,
  d.Visit AS `Visit`,
  d.SMForm AS `Study Treatment Form`,
  d.FirstDoseDate AS `First Dose Date`,
  d.PMS1Form AS `PMS1 form`,
  d.PMSDate AS `PMS1 Date of Assessment`,
  d.DS01Date AS `DS01 Date`,
  d.DS01Status AS `DS01 Status`,
  d.ErrorMessage AS `Error Message`
FROM
  (

-- Logic 1: Subject/Medication Status Missing -- no matching PMS record found for the SM first-dose record
SELECT
      `@HDR`.`Site`.`Country` AS Country,
      `@HDR`.`Site`.`Number` AS Site,
      `@HDR`.`Subject`.`Name` AS SubjectNumber,
      `@HDR`.`Event`.`Name` AS Visit,
      `@Form`.`Name` AS SMForm,
      SMEXSTDTCIT AS FirstDoseDate,
      'PMS1' AS PMS1Form,
      CAST(NULL AS STRING) AS PMSDate,
      DATE_FORMAT(RAWDATE(DS01.DS01DSSTDTCLCIT), '%d-%m-%Y') AS DS01Date,
      'Medication Status Missing' AS DS01Status,
      'Subject/Medication Status Missing' AS ErrorMessage
    FROM `EDC`.`SMFM` SM
    JOIN `EDC`.`DS01FM` DS01
      ON DS01.`@HDR`.`Subject`.`ID` = SM.`@HDR`.`Subject`.`ID`
    WHERE SM.`@Form`.`Status` = 'submitted__v'
      AND DS01.`@Form`.`Status` = 'submitted__v'
      AND (SM.DELETEDFM = 'N' OR SM.DELETEDFM IS NULL)
      AND (DS01.DELETEDFM = 'N' OR DS01.DELETEDFM IS NULL)
      AND DS01.DS01DSTERMCMPIT IS NOT NULL
      AND DS01.DS01DSTERMCMPIT NOT LIKE '%Screen Failure%'
      AND SM.SMEXSTDTCIT IS NOT NULL
      AND SM.SMEXFDINDCCB = 'First Dose'
      AND NOT EXISTS (
        SELECT 1
        FROM `EDC`.`PMS1FM` PMS
        WHERE PMS.`@HDR`.`Subject`.`ID` = SM.`@HDR`.`Subject`.`ID`
          AND PMS.`@Form`.`Status` = 'submitted__v'
          AND PMS.PMS1DSTERMSTATIT IS NOT NULL
      )

    UNION ALL

-- Logic 2: Subject/Medication Status Mismatch -- PMS Date of Assessment after DS01 Date of Disposition
SELECT
      `@HDR`.`Site`.`Country` AS Country,
      `@HDR`.`Site`.`Number` AS Site,
      `@HDR`.`Subject`.`Name` AS SubjectNumber,
      `@HDR`.`Event`.`Name` AS Visit,
      CAST(NULL AS STRING) AS SMForm,
      CAST(NULL AS STRING) AS FirstDoseDate,
      'PMS1' AS PMS1Form,
      DATE_FORMAT(RAWDATE(PMS.PMS1DSDTCIT), '%d-%m-%Y') AS PMSDate,
      DATE_FORMAT(RAWDATE(DS01.DS01DSSTDTCLCIT), '%d-%m-%Y') AS DS01Date,
      'Subject/Medication Status Mismatch' AS DS01Status,
      'Subject/Medication Status Mismatch' AS ErrorMessage
    FROM `EDC`.`DS01FM` DS01
    JOIN `EDC`.`PMS1FM` PMS
      ON PMS.`@HDR`.`Subject`.`ID` = DS01.`@HDR`.`Subject`.`ID`
    WHERE DS01.`@Form`.`Status` = 'submitted__v'
      AND PMS.`@Form`.`Status` = 'submitted__v'
      AND (DS01.DELETEDFM = 'N' OR DS01.DELETEDFM IS NULL)
      AND DS01.DS01DSTERMCMPIT IS NOT NULL
      AND DS01.DS01DSTERMCMPIT NOT LIKE '%Screen Failure%'
      AND DS01.DS01DSSTDTCLCIT IS NOT NULL
      AND PMS.PMS1DSDTCIT IS NOT NULL
      AND PMS.PMS1DSTERMSTATIT IS NOT NULL
      AND RAWDATE(PMS.PMS1DSDTCIT) > RAWDATE(DS01.DS01DSSTDTCLCIT)

    UNION ALL

-- Logic 3: DS01 Status missing -- PMS shows "Not Continuing" but DS01 subject status is null
SELECT
      `@HDR`.`Site`.`Country` AS Country,
      `@HDR`.`Site`.`Number` AS Site,
      `@HDR`.`Subject`.`Name` AS SubjectNumber,
      `@HDR`.`Event`.`Name` AS Visit,
      CAST(NULL AS STRING) AS SMForm,
      CAST(NULL AS STRING) AS FirstDoseDate,
      'PMS1' AS PMS1Form,
      DATE_FORMAT(RAWDATE(PMS.PMS1DSDTCIT), '%d-%m-%Y') AS PMSDate,
      CAST(NULL AS STRING) AS DS01Date,
      'DS01 Status missing' AS DS01Status,
      'DS01 Status missing' AS ErrorMessage
    FROM `EDC`.`PMS1FM` PMS
    JOIN `EDC`.`DS01FM` DS01
      ON DS01.`@HDR`.`Subject`.`ID` = PMS.`@HDR`.`Subject`.`ID`
    WHERE PMS.`@Form`.`Status` = 'submitted__v'
      AND DS01.`@Form`.`Status` = 'submitted__v'
      AND (DS01.DELETEDFM = 'N' OR DS01.DELETEDFM IS NULL)
      AND DS01.DS01DSTERMCMPIT NOT LIKE '%Screen Failure%'
      AND PMS.PMS1DSTERMSTATIT LIKE 'Not Continuing%'
      AND DS01.DS01DSTERMCMPIT IS NULL
  ) d
ORDER BY d.Country, d.Site, d.SubjectNumber

Explanation:
Because no supporting-document data was supplied at generation time, this query hardcodes PMS1FM as the PMS form and SMFM as the Study Medication form (per the example row "Medication Status,PMS1,...,SM|SMAU") and uses PMS1DSTERMSTATIT as the "PMS Itemquestion" (Status of Subject/Medication at End of This Trial Segment) and DS01DSTERMCMPIT as DS01's "Status of the Subject for the Study" -- these should be confirmed via DESCRIBE FORM since the supporting-doc-driven Status/PMSf/PMSv/SM Form mapping (which can vary per subject via the CSV) could not be dynamically implemented in static CQL and is only approximated here for the single PMS1/SM example row shown. Screen Failure exclusion is done via DS01DSTERMCMPIT NOT LIKE '%Screen Failure%', deleted records are excluded via DELETEDFM = 'N' OR NULL, and each of the three Logic blocks (Missing/Mismatch/DS01-missing) is implemented as a UNION ALL branch producing the Column 10 status text as specified; erroneous-visit exclusion, the Randomized-only/Country/Site/Subject/Supporting-Doc-Page parameters, and full per-row supporting-document-driven PMSf/PMSv/SM-Form matching were not implemented since the actual supporting CSV values and an erroneous-visit flag item were not provided in metadata -- these should be added once the real supporting document and visit-erroneous-flag item are confirmed.
