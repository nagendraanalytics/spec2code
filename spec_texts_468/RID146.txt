Report ID: RID146

Report Title:
Missing oncologic signs and symptoms at specific visit/timepoint per protocol

Description:
This report will list subjects who are missing oncologic signs and symptoms that should be assessed at any visit and/or timepoint specified per protocol.

Column Heading:
1. Country

2. Site

3. Subject Number

4. Visit

5. DOV

6. Expected OSS timeframe

7. Scenario

Logic:
Logic 1:

DOV.visitmnemonic <> NULL AND visit is not erroneous

AND

THERE IS NOT ANY record in OSS eCRF with OSS.Date of assessment <> NULL and within the window of days from DOV.visitmnemonic specified in supporting document. (Columns 7, 8 and 9 from supporting document).

Logic 2:

Follow up DOV.visitmnemonic <> Null AND visit is not erroneous

AND PMS1.Date of Assessment <> Null

AND PMS1.Status of Study Medication at the End of This Trial Segment <> Progressive Disease or Clinical Progression.

AND

THERE IS A MISSING OSS.Date of assesment at a specific timepoint from Follow up DOV.Visitmnemonic and +/- days of window as provided in the supporting document. (Columns 8, 9 and 10 from supporting document when scenario is scenario 2).

Logic 3:

Survival DOV.visitmnemonic <> Null and visit is not erroneous

AND

THERE IS A MISSING OSS.Date of assesment at a specific timepoint and +/- days of window as provided in the supporting document (Columns 8, 9 and 10 from supporting document when scenario is scenario 3).

Requires supporting document to be named ONC_OSS_002_supp_<xxxxxxx>.csv. It will contain the following columns and associated content:

1. CriteriaForm1: Form with criteria that report will use to distinguish groups of patients (eg. SR/TRIG); If applies for all subjects regardless the Arm/Cohort/Stratification, enter NA OR if the CriteriaForm1 is not applicable for the protocol, enter NA.

2. CriteriaItemquestion1: Item within 'Criteria Form' that will allow to distinguish different groups of patients (eg. Arm/Cohort/Stratification); If applies for all subjects regardless the Arm/Cohort/Stratification, enter NA OR if the CriteriaItemquestion1  is not applicable for the protocol, enter NA.

3. CriteriaValue1: Value for “CriteriaItemquestion” (eg. Cohort D in item 'Cohort' on SR eCRF); If applies for all subjects regardless the Arm/Cohort/Stratification, enter NA OR if the CriteriaValue1 is not applicable for the protocol, enter NA.

4.  CriteriaForm2: Form with criteria that report will use to distinguish groups of patients (eg. SR/TRIG); If applies for all subjects regardless the Arm/Cohort/Stratification, enter NA OR if the CriteriaForm2 is not applicable for the protocol, enter NA.

5. CriteriaItemquestion 2: If applicable, it is a second Item within 'Criteria Form' that will allow to distinguish different groups of patients (eg. A specific Arm within a specific Cohort);  If applies for all subjects regardless the Arm/Cohort/Stratification, enter NA OR if the CriteriaItemquestion 2 is not applicable for the protocol, enter NA.

6. CriteriaValue 2: Value for “CriteriaItemquestion 2” (eg. Arm 2 in item “Arm” on SR eCRF); If applies for all subjects regardless the Arm/Cohort/Stratification, enter NA OR if the CriteriaValue 2 is not applicable for the protocol, enter NA.

7. Visitmnemonic: Visitmnemonic from T&E

8. Lower Window: Allowed lower window for assessment to be done without sign +/-. If there is no window, fill NA.

9. Upper Window: Allowed upper window for assessment to be done without sign +/-. If there is no window, fill NA.

10. Expected timeframe: Number of weeks per protocol for each assessment during FU/Survival. For Scenario 1 fill NA

11. Scenario: Fill 1, 2 or 3

Notes

1. Output should be fired for deleted entries in OSS.

2. Output should not be fired for Survival follow up for dates after DS01 is initialized.

3.For logic 2 Output should not be fired for Follow up phase after PMS1A/OEDRA is completed.

4. Output should not be fired if visit is erroneous.

5. In the output, show the “expected timeframe” only for Follow up and Survival visits (Scenario 2 and 3) in format "DD-MMM-YYYY to DD-MMM-YYYY"

6. In the logic 2 and 3 “specific timepoint” refers to the number of weeks as per the supporting document.

7. For Scenario 2 and 3 expected OSS should count since DOV.visitmnemonic

8. Report is not a listing; It should show outputs only for missing OSS records based on logic and supporting document, an output is not expected if a record is already present.

Scenario 1

Output Yes: Missing OSS.Date of assessment at specific visits within Screening, Cycles, Discontinuation Visit and Follow-up Day 30.

Output No: OSS.Date of assessment is completed at specific visits within Screening, Cycles, Discontinuation Visit and Follow-up Day 30.

Scenario 2:

Output No: OSS.Date of assessment is completed at specific timepoint within Follow Up phase from PMS1 date of Assessment if reason for discontinuation is other than Progressive Disease or Clinical Progression.

Scenario 3

Output Yes:  Missing OSS.Date of assessment at specific timepoint within Survival phase on or/and after visit DOV.

Output No: OSS.Date of assessment is completed at specific timepoint within Survival phase on or/and after visit DOV.
