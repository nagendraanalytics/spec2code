Report Title:
Tab 1: PK Invoice and BA Vendor Reconciliation

Description:
This report will output mismatches between INFORM, Central Lab and/or BA vendor.

In case all 3 databases need to be reconciled (Inform - BA file and Central Lab), the report will show 2 TABS: eCRF Invoice VS BA file and eCRF invoice VS Central Lab.

Logic:
This report displays subjects who have mismatches for either Visit, Subject Number, Schedule Time, Analyte, Date and Time of Sample Collection and/or Specimen Type between Inform vs BA vs Central. The following scenarios should be look into:

The initial comparison should be Subject Assignment. Screening Number+ Subject Assignment. Specimen ID vs SCRNID+ REFID. Then the following scenarios should be look into:

1.	Scheduled Time different than NOMHOUR (BA/Central). If different, output should be produced, and Scenario displayed as Schedule Time mismatch.

2.	IF Visit Mnemonic is different than NOMDAY, output should be produced, and Scenario displayed as Visit mismatch.

3.	IF Analyte is different than ANALYTE, output should be produced, and Scenario displayed as Analyte mismatch.

4.	IF Date and Time of Sample Collection-Date is different than DDT, output should be produced, and Scenario displayed as Date mismatch.

5.	IF Date and Time of Sample Collection-Time is different than DTM, output should be produced, and Scenario displayed as Time mismatch.

6.	IF Specimen Type is different than SAMPLE, output should be produced, and Scenario displayed as Specimen Type mismatch.

7.	If Treatment/Randomization Number is different than SUBJID, output should be produced, and Scenario displayed as PNE.

Notes:

1.	Please use the Supporting Document as guide to see which visit corresponds to the NOMDAY, the Schedule Time to the NOMHOUR and Analyte and Specimen Type matching.

2.	Exclude samples from Inform when deleted records OR “If Sample Was Collected But Not Sent”, “Check if Sample Was Not Collected” is different than NULL.

3.	DOV should be initialized, and visit should not be erroneous for all scenarios.

4. For PNE scenario subject number should be displayed from Vendor files “SITEID+“--"+ SUBJID”.

5. No case sensitive when comparing Specimen ID from INFORM and Vendor data.

6. SITEID is always a 4-digit number, SCRNID is a 9-digit number and SUBJID is a 6-digit number if any of them have a smaller number of digits please complete with zeros at the left to make the comparison, i.e. SITEID: 100 should be 0100 to match with Site from InForm

7.	It should be one tab for BA and another for Central Lab if data of both is included using the prompts.

8.	For the same Subject Assignment. Screening Number+ Subject Assignment. Specimen ID it should show all the discrepancies in only one output concatenating the issue messages i.e. “Visit Mismatch, Analyte mismatch, Specimen Type mismatch”.

9.	If Scheduled Time in Inform is “UNSCHEDULED”, for Visit mismatch scenario please use Unscheduled as Visit Mnemonic in the logic based on the relation (Visit Mnemonic-NOMDAY) present in the supporting document. The report output should display the real visit mnemonic in which the record in InForm is found. If Unscheduled is not included in the supporting document, please use the relation Unscheduled (Visit Mnemonic) – 997 (NOMDAY).

10.	For PK05 form, scenarios of date and time of collection, report should check DDT and DTM against the item selected by user in the prompts.

11.	If the trial does not collect the time in Inform, this scenario should not be evaluated, and outputs are not expected for Time mismatch scenario.

1. Analyte Inform

2. Analyte BA/Central

3. Visit Mnemonic - Please include all timepoints from specification. i.e. Unscheduled, Discontinuation, Early Discontinuation, etc..

4. NOMDAY

5. Scheduled Time

6. NOMHOUR

7. Specimen Type Inform

8. Specimen Type BA/Central

Note to LCDM: NOMDAY and NOMHOUR should match with the NOMDAY NOMHOUR specification sent to vendor. Please refer to 600-GDMS018-062.

Each pair of columns in supporting document is independent of the others (1&2, 3&4, 5&6, 7&8) and they could have different amount of rows
