2. LOGIC UNDERSTANDING
======================================================================

This report identifies, per Treatment Phase, subjects who reached a baseline visit/assessment (via DOV.Date of Visit for the phase's First Visit Mnemonic or SR.Date of Assessment, per configuration) but lack a qualifying measurable lesion record. Logic 1 is a simple existence check (any LSN eCRF at all), while Logic 2 tightens this to require an LSN eCRF whose Date of Initial Identification falls within a configurable day-window prior to baseline AND whose lesion category/tumor identification matches a configured Lesion Type -- both sub-conditions must hold together for a record to count as satisfying baseline lesion evaluation. The report relies heavily on two external supporting documents (study phase and report-specific) to drive per-phase, per-form, per-window, per-lesion-type logic, and outputs are separated by Treatment Phase, with erroneous/deleted records excluded and a specific fallback message if the report-specific supporting document is missing.


1. For each Treatment Phase (as defined in the Study Phase Supporting Document, e.g., Initial Treatment Phase, Second Course Phase, Crossover), determine the baseline date: either the DOV.Date of Visit for that phase's First Visit Mnemonic, or the SR.Date of Assessment, whichever is designated as the 'Date of Assessment eCRF' for that phase in the report-specific supporting document.
2. Logic 1 check: if that baseline date (DOV or SR) is NOT NULL for the subject/phase, AND the subject has no record at all on any of the configured 'LSN eCRF' forms (e.g., LSNIR, LSNEV, etc. per the supporting doc row for that phase), then flag the subject as having no measurable lesion at baseline -- this corresponds to Scenario 1 (Output = Yes).
3. Still under Logic 1, if the baseline date is NULL (both DOV and SR are null for that phase), the subject is NOT flagged even if no LSN eCRF exists, because there's no evaluable baseline visit to compare against -- this is Scenario 2 (Output = No).
4. Also under Logic 1, if the baseline date is not NULL but the subject DOES have at least one initiated LSN eCRF (existence only, no date/type check), the subject is not flagged -- this is Scenario 3 (Output = No).
5. Logic 2 refines the check by requiring not just existence of an LSN eCRF, but a QUALIFYING LSN eCRF: one whose 'Date of Initial Identification' falls within [X] days prior to the baseline date (DOV or SR) AND whose 'Lesion Category'/'Tumor Identification' matches one of the 'Lesion Type' values configured for that phase in the supporting document.
6. Scenario 4 shows that if the baseline date is not NULL, and no LSN eCRF has a 'Date of Initial Identification' within the [X]-day window prior to that date, the subject is flagged (Output = Yes) -- this is a failure of the date-window sub-condition alone.
7. Scenario 5 shows that if the baseline date is not NULL, and no LSN eCRF has a matching 'Lesion Category'/'Tumor Identification' equal to a configured 'Lesion Type', the subject is flagged (Output = Yes) -- this is a failure of the lesion-type sub-condition alone.
8. Combining steps 6 and 7: an LSN eCRF only 'counts' as satisfying the baseline lesion requirement under Logic 2 if it satisfies BOTH the date-window condition AND the lesion-type match condition simultaneously (on the same record); satisfying only one is not enough to avoid being flagged. (inferred)
9. Scenario 6 confirms the negative case: if the baseline date is not NULL and there IS an LSN eCRF meeting both the date-window and lesion-type conditions together, the subject is NOT flagged (Output = No).
10. Per Note 2, before applying any of the above, exclude any erroneous or deleted visit/records from consideration entirely -- they should not count toward either the baseline date determination or the LSN eCRF existence/match checks.
11. Per Note 4, the entire Logic 1/Logic 2 evaluation (steps 1-10) must be repeated and reported separately for each Treatment Phase defined for the trial, rather than combined into a single subject-level flag.
12. Per Note 3, before running any of this logic, first check whether the report-specific supporting document (ONC_LSN_012_supp_<MKxxxxxxx>.csv) exists for the trial; if not, skip all logic and output only the message 'ONC_LSN_012_JR_STD Supporting Document Not Present for This Trial'.
13. When a supporting document row has 'Lesion Type' = NA, treat the lesion-type match sub-condition in Logic 2 as automatically satisfied (any Lesion Category/Tumor Identification value is acceptable), per the column definition note.
