Report ID: RID050

Report Title:
Missing or Mismatched Dispense vs Study medication entries

Description:
This report displays subjects who have mismatches or missing records between study medication and dispense based on Date.

Column Heading:
1. Country

2. Site

3. Subject Number

4. Study Medication

5. DISP Form

6. DISP Visit

7. DISP Seq

8. Dispense date

9. SM Form

10. SM Visit

11. SM Seq

12. SM Start Date

13. Error message

Logic:
Scenario 1 - For trials that dispense is done each time Study Medication is administered, with "Coincide"  as Yes in the supporting doc.

This scenario checks there is no record about study medication on <DISP/SM> form, with Dispense Date is within specific window prior to Start Date of Study Medication.

Logic 1: No DISP

Logic 1.1: "SM Form".Study Medication="Study Medication"

AND

Logic 1.2: "SM Form".Start Date/Time is not null

AND

There is no DISP record meet below criteria:

Logic 1.3: "DISP Form".Study Medication = "Study Medication"

AND

Logic 1.4: "DISP Form". Visitmnemonic = "SM Form". Visitmnemonic

AND

Logic 1.5: "DISP Form".Date Dispensed >= "SM Form".Start Date/Time - "Window of Days"

AND

Logic 1.6: "DISP Form". Date Dispensed <= "SM Form".Start Date/Time

OR

Logic 2: No SM/Medication Discontinued

Logic 2.1: "DISP Form".Study Medication = "Study Medication"

AND

Logic 2.2: "DISP Form". Date Dispensed is not null

AND

There is no SM record meet below criteria:

Logic 2.3: "SM Form". Study Medication = "Study Medication"

AND

Logic 2.4: "SM Form". Visitmnemonic = "DISP Form". Visitmnemonic

AND

Logic 2.5: "SM Form".Start Date/Time >= "DISP Form". Date Dispensed

AND

Logic 2.6: "SM Form".Start Date/Time <= "DISP Form". Date Dispensed + "Window of Days"

Scenario 2 - For trials that Dispense Date does NOT need to match study medication for each administration, with "Coincide" as No in the supporting doc.

This scenario checks the Dispense Date for Study Medication is not within specific window prior to Start Date of first dose. Visit mnemonic.

Logic 3: First dose not match

Logic 3.1: "SM Form".Study Medication="Study Medication"

AND

Logic 3.2: "SM Form".Start Date/Time = MIN "SM Form".Start Date/Time

AND

Logic 3.3: "SM Form".Please Indicate if this is the First Dose for this Study Medication is checked.

AND

Logic 3.4: "DISP Form". Study Medication = "Study Medication"

AND

Logic 3.5: "DISP Form".Date Dispensed = MIN "DISP Form". Date Dispensed

AND

Logic 3.6: "DISP Form". Visitmnemonic = "SM Form". Visitmnemonic

AND

(

Logic 3.7: "DISP Form". Date Dispensed < "SM Form".Start Date/Time - "Window of Days"

OR

Logic 3.8: "DISP Form". Date Dispensed > "SM Form".Start Date/Time

)

Note:

1) "DISP Form", "SM Form", "Study Medication", "Window of Days","Coincide" are from supporting document

2) Exclude deleted data and erroneous visit from programming.

3) Only date will be considered in this report.

4) Exclude SM/SMAU/SMAB zero dose.

5) For Logic 2, if "SM Form". Please Indicate if this is the Last Dose for this Study Medication is checked, and DISP.Date > SM Last Dose Date, the Error Message show as "Medication Discontinued ", otherwise, show as "No SM".

6) For Logic 3, MIN "SM Form".Start Date/Time and MIN "DISP Form".Date Dispensed are both calculated within same form and study medication

7) If Multiple SM Allowed is provided as Yes in the supporting doc for study medication, do not output when there are multiple SM records for the same medication in a visit, and there is already record in DISP that matches with that SM.

8)The report logic should be checked within the same treatment phase defined in the supporting document.

For example, if user provides two Treatment Phases in supporting document like below:

Phase Order, Treatment phase, First Visitmnemonic of Treatment Phase

1,Initial Treatment Phase,Cycle 1

2,Second Course Phase,Second Course Cycle 1

The treatment phase will be identified as following:

Initial Treatment Phase: Cycle 1 <= Form.Date < Second Course Cycle 1

Second Course Phase: Second Course Cycle 1 <= Form.Date

Form.Date include: SM Form.Start Date/Time, DISP Form. Date Dispensed

9) AS for SM, Visit Mnemonic will be assigned based on Start Date/Time and DOV.Date of Visit. eg: if Visit1.Date of Visit < SM1.Start Date < Visit2.Date of Visit, then Visit1 will be assigned as SM1 Visit Mnemonic

10)when there are multiple DISP records on the same day, all of them should appear on output

11)logic 1.4, 2.4 and 3.6 are optional when different parameter selected. When 'If compare DISP and SM in same visit?' selected as yes, report just check DISP and SM in same visit; otherwise, report will compare DISP and SM date with ignoring the assigned visit

12)Report requires supporting document to be named DISP005_supp_<xxxxxxx>.csv and will contain the following columns and associated content:

1. DISP Form - Required, enter DISP<A,B>

2. SM Form - Required, enter SM/SMAB/SMAU

3. Study Medication  -  Required, SM/SMAB/SMAU.Study Medication

4. Window of Days – Required, enter window of days allowed for Administration

5. Coincide – Required, enter Yes/No, specify as Yes if dispense is done each time Study Medication is administered; specify as No if Dispense date does not need to match study Medication for each administration

6. Multiple SM Allowed – Required, enter Yes/No, specify as Yes if Study Medication is dispensed one time per visit but there is a possibility to have multiple SM records; specify as No if for each SM record within a visit, it is expected to have a DISP record

e.g.

DISP Form,SM Form,Study Medication,Window of Days,Coincide,Multiple SM Allowed

DISP,SM,-1439,0,No,No

DISP,SMAB,-3475/Placebo,1,Yes,No

DISP,SMAB,-3475/Placebo,1,Yes,No

DISPA,SMAU,Carboplatin,3,No,Yes

The number of rows in the supporting document will be represented in the Report Header as "# of rows for customization".

The actual information provided by the supporting doc can be outputted by selecting Y in the parameter "Supporting doc Page".

13)The supporting document is required for all trials if treatment phase is applied to logic，even if only one treatment phase is present.

This supporting document is only required to be created once per trial. If it was already created and uploaded, there is no need to duplicate it.

The supporting document should be named as study_phase_supp_<xxxxxxx>.csv and will contain the following columns and associated content:

One row for each Treatment Phase

1. Phase Order: required, the order on which phases will appear on protocol

2. Treatment Phase: name of each study phase (Intial Treatment Phase, Neodjuvant Phase, Second Course Phase)

3. First Visitmnemonic of Treatment Phase: required,the first visit on which treatment is expected to be administered on each phase.

e.g.

1, Initial Treatment Phase, Cycle 1

2, Second Course Phase, Cycle 1 Course 2

3, Crossover Phase, Crossover Cycle 1

The actual information provided by the supporting doc can be outputted by selecting Y in the parameter "Study Phase Page".

14)This report can also use the optional Study medication supporting document. It is only required in the following cases:

- SM Label Description and SMAU/SMAB Dose Number are not exactly matched with Study Medication.

This supporting document is only required to be created once per trial. If it was already created and uploaded, there is no need to duplicate it.

Optional* supporting document should be named as study_med_match_supp_<xxxxxxx>.csv and will contain the following columns and associated content:

* supporting document study_med_match_supp_<XXXXXXX>.csv must be created if:

- Your trial has at least one study medication that is given in different doses/bags (e.g. 5-FU given in 4 different bags with different Dose numbers)

- SMA study medication is populated via edit check by SMP form. Because it is prefer to use dose number/label description, since, it is not always the same as study medication.

1 row for each Label Description or Dose Number present in SM/SMAU/SMAB eCRFs.

1. eCRF – SM/SMAU/SMAB

2. Study Medication – Value of Study Medication

3. Matching Item – SM Label Description or SMAU/SMAB Dose Number

4. Matching Value – Value of SM Label Description or SMAU/SMAB Dose Number

e.g.

eCRF,Study Medication,Matching Item,Matching Value

SM,-1439,Label Description,-1439 100 mg

SM,Methadone,Label Description,Methadone Tablet 5 mg

SM,Methadone,Label Description,Methadone Tablet 10 mg

SMAB,3475/Placebo,Dose Number,3475/Placebo

SMAU,Carboplatin,Dose Number,Carboplatin

SMAU,Carboplatin,Dose Number,Carboplatin - Dose 1

SMAU,Carboplatin,Dose Number,Carboplatin - Dose 2

SMAU,Carboplatin,Dose Number,Carboplatin - Dose 3

The actual information provided by the optional supporting doc can be outputted by selecting Y in the parameter "Study Med Match Page"

15) Exclude screening visit from programming
